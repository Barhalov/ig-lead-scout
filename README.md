# IG Lead Scout

Исходники текущего парсера Instagram (расширение Manifest V3, версия 5.98.2) и локального координатора. Репозиторий подготовлен для передачи и совместной доработки. Личная база, браузерные профили, cookies, Telegram-сессии и ключи автора не включены.

## Быстрый запуск

Нужны Python 3.10+ и Chrome либо Edge. Python-зависимости используют стандартную библиотеку, `pip install` не требуется.

```sh
git clone https://github.com/Barhalov/ig-lead-scout.git
cd ig-lead-scout
python setup_local.py
python bridge.py
```

1. Откройте `chrome://extensions` или `edge://extensions`.
2. Включите режим разработчика → **Загрузить распакованное** → папка `ig-lead-scout`.
3. Войдите в свой Instagram вручную.
4. Откройте страницу `laptop.html` установленного расширения: `chrome-extension://ВАШ_ID/laptop.html`. ID отображается в списке расширений и может отличаться от ID у автора.
5. Укажите username публичного донора и нажмите **Запустить**. Режим по умолчанию — подписки; поисковое слово — `тренер`; порог — 3000 подписчиков.
6. Смотрите результаты через **Полный интерфейс парсера** (`dashboard.html`) и выгружайте CSV. Кнопка **Остановить** на `laptop.html` останавливает локальный поток.

Сначала рекомендуется проверить один аккаунт и один поток. Для нескольких аккаунтов используйте разные браузерные профили; на один профиль — один поток. Все профили должны использовать эту установку расширения и один координатор `127.0.0.1:8766`, чтобы разделять проверки и доноров. Восемь браузеров требуют заметного объёма памяти.

`setup_local.py` создаёт **новую пустую** базу и случайный токен для локального соединения. Повторный запуск сохраняет уже созданную базу и токен. Личные настройки не публикуются благодаря `.gitignore`.

## Как устроена обработка

1. Страница донора открывает список подписок и применяет поиск `тренер`.
2. Расширение собирает кандидатов и запрашивает у координатора `/claim` право на проверку. Общий SQLite-кеш исключает одновременные дубли между профилями.
3. Быстрая фоновая вкладка читает число подписчиков. Профили ниже 3000 отсеиваются; для остальных раскрывается описание и дополнительные ссылки.
4. `/profile` проверяет приватность, порог, действительные Telegram-ссылки и текущие языковые/географические фильтры из `v2/niches.py`.
5. Подходящий новый профиль сохраняется в SQLite. Повторный username не создаёт новую запись. Старый результат с чужим claim-токеном отклоняется.
6. `/donor` резервирует текущего донора между потоками. По исчерпании списка выбирается следующая цепочка. Журнал и watchdog помогают искать зависания.

## Карта файлов

| Файл | Назначение |
| --- | --- |
| `ig-lead-scout/content.js` | Интерфейс на Instagram, поиск в списках, очередь, АФК и переходы доноров |
| `ig-lead-scout/background.js` | Фоновые вкладки, quick-check, сообщения расширения |
| `ig-lead-scout/laptop-profile.js`, `laptop-entry.js` | Раннее чтение профиля, подписчики, раскрытие bio и ссылок |
| `ig-lead-scout/laptop-background.js` | Координатор, очередь отправки результатов, статусы и watchdog |
| `ig-lead-scout/laptop-page.js`, `laptop.html` | Запуск и остановка одного потока |
| `ig-lead-scout/dashboard.*`, `popup.*` | Просмотр, настройки и CSV |
| `bridge.py` | Локальный HTTP-приёмник, квалификация, shared-check и donor leases |
| `v2/database.py`, `models.py`, `links.py`, `niches.py` | Схема базы, модель лида, ссылки и фильтры |
| `setup_local.py` | Генерация частной конфигурации и пустой базы |
| `test_*.py`, `test_*.cjs` | Проверки квалификации, очереди и чтения профиля |

Нужные иконки, JS-библиотеки и WASM-ресурсы находятся в `ig-lead-scout/icons` и `ig-lead-scout/lib`. Дополнительные OCR/Telegram-модули расширения сохранены как исходники; они требуют своих настроек и не нужны для базового парсинга. Личная внешняя инфраструктура автора (Telegram-бот, автозапуск Windows, аккаунты и телефонные сессии) не переносится.

## Локальные данные и диагностика

- `data/bot.sqlite3` — ваша новая база лидов;
- `check-queue.sqlite3` — права на проверку, кеш результатов и доноры;
- `events.jsonl` — события `check_claimed`, `content_ready`, `header_ready`, `profile_result`, `lead_saved`, `check_timeout`;
- `bridge.log` — ошибки приёмника;
- хранилище расширения — локальные профили, состояние цепочек и outbox.

Не коммитьте эти файлы, `bridge-config.json`, `laptop-config.js`, токены и браузерные профили. Список `excluded_donors` в частном `bridge-config.json` позволяет исключать username доноров. Изменения конфигурации приёмника требуют его перезапуска.

Количество открытых вкладок не показывает полезную скорость. Сравнивайте завершённые `profile_result`, причины отказа и `lead_saved`. Таймаут означает незавершённую проверку, а не неподходящего человека. Instagram может менять разметку и ограничивать загрузку списков; эта версия не гарантирует отсутствие таймаутов и блокировок. Расширение требует доступ к страницам для чтения профилей; проверяйте разрешения перед установкой.

## Разработка и ветки

Для работы без доступа на запись: нажмите **Fork**, клонируйте свой fork, создайте ветку и отправьте Pull Request в этот репозиторий.

```sh
git switch -c feature/parser-improvements
# изменения и проверки
git add .
git commit -m "Improve parser"
git push -u origin feature/parser-improvements
```

Чтобы пушить ветки непосредственно в `Barhalov/ig-lead-scout`, владелец должен отдельно добавить разработчика через **Settings → Collaborators**. Сам факт публичности репозитория такого права не даёт.

Проверки (после `python setup_local.py`; для JS нужен Node.js):

```sh
python -m unittest test_bridge.py test_portable.py
node test_quick_profile.cjs
node test_bio.cjs
node test_filtered_list.cjs
node test_idle_recovery.cjs
```

Core-логика перенесена из текущей локальной установки. Для независимого запуска добавлена генерация конфигурации/пустой базы, убраны личные значения и подготовлена документация. Стабильность живого парсинга на другом компьютере отдельно не проверялась.
